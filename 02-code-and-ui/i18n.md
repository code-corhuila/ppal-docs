# Internationalization and UI Copy

## MVP language and decision

PantryPal's H2 prototype and current MVP use English UI copy. The application must not scatter user-visible text literals through templates and feature logic: strings are defined centrally in the `src/assets/i18n/en.json` resource (or the equivalent single resource location approved in implementation) and referenced by stable, namespaced keys.

Example keys:
- `pantry.title`
- `pantry.loading`
- `pantry.empty.title`
- `pantry.loadError.retry`
- `product.form.name.label`
- `product.form.name.required`
- `product.save.failed`
- `product.delete.confirm.title`
- `product.delete.failed.retry`
- `product.expiration.expired`
- `product.expiration.expiringSoon`
- `product.expiration.notSoon`
- `product.expiration.noDate`

A thin UI text-access layer may be used to resolve these keys, but the MVP does not promise a runtime language selector. Do not introduce a translation library solely for a future capability unless it is justified and recorded.

## Rules

- No user-facing copy is hardcoded directly in multiple templates or services.
- Keep keys namespaced by feature and purpose; do not use whole English sentences as keys.
- Keep all labels, validation errors, empty/error states, confirmation dialogs, and accessibility labels in the central resource.
- Format calendar dates and numbers using locale-aware APIs. Product expiration dates remain date-only domain values and must not shift because of UTC conversion.
- Adding another locale requires a full translation of every key and a layout check for longer text; right-to-left support is not a committed MVP feature unless a locale requiring it is added.

## Verification checklist

- [ ] All current MVP copy is represented by resource keys.
- [ ] No visible labels or failure messages remain duplicated as inline literals.
- [ ] Labels and validation messages remain readable when text scales.
- [ ] Dates and quantities use locale-aware formatting.
