## Go / No-Go

### Code and tests

- [x] MVP CRUD functions were manually verified against the local PostgreSQL-backed API on the earlier tested app revision.
- [x] The earlier app revision passed 22 unit tests across 6 files, lint, web build, and Android debug build.
- [x] The API passed 9 automated HTTP tests and a TypeScript build locally.
- [ ] Re-run `npm run test:ci`, `npm run lint`, `npm run build`, and `npm run build:android:debug` after pulling the latest native port/adapter commits. Prior results predate those new changes.
- [ ] Measure coverage for the app domain and presentation/ViewModel logic; the course reference uses an 80% target. Do not infer coverage from test count.
- [ ] Execute remaining acceptance cases: empty pantry, invalid form, no-results search, date boundaries, API failures/retry, dirty-form navigation, haptic failure, and hardware-back behavior.
- [ ] Resolve the H3 requirement interpretation for two permission-sensitive native plugins and just-in-time permission tests. Current Haptics and Status Bar plugins do not require runtime permissions; camera, geolocation, notifications, and login remain excluded by ADR-002.
- [ ] Add an automated PostgreSQL integration test suite; current API HTTP tests use an in-memory repository.

### Quality and security

- [x] Android debug cleartext permission is isolated to `android/app/src/debug/AndroidManifest.xml`; the main manifest does not enable cleartext.
- [x] API binds to host loopback at `127.0.0.1:3000`; PostgreSQL is internal to the Compose network.
- [x] No login token or offline product cache is implemented in the MVP; token-storage/logout checks are not applicable to current functionality.
- [ ] Triage npm audit findings (mobile install: 6 findings; API install: 4 findings, including 2 critical). Do not use `npm audit fix --force` without review.
- [ ] The production API URL is a reserved placeholder: `https://api.pantrypal.invalid/api`. Replace only after a controlled HTTPS API deployment exists.
- [ ] Verify a production merged Android manifest has cleartext traffic disabled.
- [ ] Review `allowBackup`, R8/minification, release logging, permissions, and other production manifest settings before any public release.

### Build and signing

- [x] Local Android debug APK built and installed on Pixel 10 Pro Android 16 / API 36.1 emulator.
- [ ] Generate a dedicated release keystore outside version control. Back up the keystore and credentials securely.
- [ ] Configure release signing through ignored local properties or protected CI secrets; never commit the keystore or passwords.
- [ ] Build `app-release.aab` and `app-release.apk` after the production endpoint and release config are ready.
- [ ] Verify AAB with `jarsigner -verify` and APK with `apksigner verify --print-certs`; capture outputs without exposing secrets.
- [ ] Check `versionName` / `versionCode`, package ID, SDK versions, app icon, budget output, and merged release manifest.
- [ ] Record artifact sizes and upload the binaries to a shareable release/storage location if generated. Do not add APK/AAB files to source control.
- [ ] iOS IPA is not built: the current workstation is Windows and no Xcode/Apple signing environment is evidenced. Document the iOS path as a simulation if it remains unavailable.

### Distribution and observability

- [ ] No public cloud deployment or store upload has occurred.
- [ ] GitHub Actions workflows exist but jobs were blocked before runner steps due to a GitHub billing lock. They are not passing checks; do not pay or add a card to continue the local academic workflow.
- [ ] Provide a truthful pipeline diagram and simulated store-distribution procedure; do not create screenshots of consoles or releases that were not used.
- [ ] Define monitoring, API health check, rollback criteria, minimum-supported-version policy, and post-release maintenance actions before a real deployment.

## Decision

- **Go / No-Go:** GO for controlled local academic demonstration only, after re-validation of the latest branch; NO-GO for public/store release.
- **Approval:** Pending instructor review.
- **Reason:** Current local CRUD works with a local API and database. Latest native port/adapter commits require local test/build revalidation. No signed release artifacts or production HTTPS backend exist, dependency findings remain open, and GitHub Actions cannot execute due an account billing lock.
